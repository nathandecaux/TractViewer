## Releases

The `Desktop` workflow ([.github/workflows/desktop.yml](../.github/workflows/desktop.yml)) builds
the desktop apps with PyInstaller ([packaging/](../packaging/)): Windows installer (Inno Setup),
macOS `.dmg` + `.zip` (arm64 and x86_64), Linux AppImage. The version lives in
`tractviewer/_version.py`.

| Action | Result |
|---|---|
| `git push` (fix, any commit) | tests only, nothing published |
| `packaging/release.sh patch` (or `minor`, `major`, `X.Y.Z`) | bump + commit + tag `vX.Y.Z` + push → builds + GitHub release |
| Actions › Desktop › *Run workflow*, `release = patch/minor/major` | same, from the GitHub page |
| Actions › Desktop › *Run workflow*, `release = none` | test builds, downloadable from the run page |

A tag with a suffix (`packaging/release.sh 1.2.0-rc1`) makes a pre-release, ignored by the
auto-updater.

Release asset names are used by the auto-updater (`tractviewer/updater.py`): keep
`TractViewer-<version>-windows-x64-setup.exe`, `-macos-<arch>.zip` and `-linux-<arch>.AppImage`.

Local build:

```bash
python packaging/fetch_vendor.py              # bundle vtk.js (offline first launch)
pyinstaller --noconfirm packaging/tractviewer.spec
packaging/linux/build_appimage.sh dist/TractViewer dist/TractViewer.AppImage   # Linux
```

Build from a clean virtual environment: PyInstaller collects every optional import it finds, and
a large environment (conda with torch, etc.) inflates the app.

## README images

`docs/web-interface.png` (interface in headless Chrome) and `docs/rotation.gif` (headless
pyvista rotation) are generated by [make_screenshots.py](make_screenshots.py):

```bash
pip install playwright        # uses the installed Chrome / Chromium, or: python -m playwright install chromium
python docs/make_screenshots.py                                    # synthetic demo data
python docs/make_screenshots.py fa.nii.gz:cmap=gray,name=FA \
    tracto.tck:name=tractogram,display_array=length_mm,cmap=plasma,clim=(30,180),max_points=600000
```

Options: `--only interface|rotation`, `--size 1440x860`, `--scale 2` (retina), `--wait MS`,
`--browser PATH`, `--gif-size`, `--frames`, `--fps`, `--out-dir`.

## Code layout

- `core.py`: `TractViewer` (datasets, plotter lifecycle, capture, rotation)
- `cli.py`: command line
- `loaders.py`: `.tck/.trk`, NIfTI, PNG and pyvista formats
- `diffusion/`: DTI / ODF / Anima MCM loading (`models.py`), glyph data for the page
  (`glyphs.py`), NRRD and `.mcm/.mcmx` readers (`io.py`), MRtrix3 SH basis (`sh.py`)
- `budget.py`: memory budget of tractograms (available RAM → automatic subsampling)
- `scene.py`: adds the datasets to the pyvista plotter (threshold, legends, contour, envelope)
- `params.py`: parameter keys, aliases, CLI syntax parsing
- `recording.py`: GIF / video writing (ffmpeg)
- `web/vtkjs.py`: serialization (meshes, arrays, volumes) and HTML export
- `web/vtkjs_template.html`: the vtk.js page (toolbar, layer list, slices, layer panel with
  contrast histogram and tract filters, isosurface, upload, GIF)
- `web/server.py`: HTTP server (standard library) with uploads
- `web/desktop.py`: native window (pywebview) around the server, local vtk.js cache
- `updater.py`: auto-update of the pre-compiled app from GitHub releases
- `linux_integration.py`: AppImage first-launch install (folder choice, menu entry, uninstall)
- `_version.py`: version (single source)
- `envelope.py`, `geometry.py`, `backend.py`, `debug.py`
